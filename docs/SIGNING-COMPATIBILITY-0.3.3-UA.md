# Сумісність підпису 0.3.3

Старий власницький APK `Fisker-Warm-Lab-0.2.0(3).apk` перевірено офіційними `apksigner` та `aapt2` з Build Tools 35.0.0:

- applicationId: `com.fiskerwarm.lab02`;
- versionCode: 3;
- versionName: `0.2.0-lab`;
- сертифікат SHA-256: `848edb87d8b74d2c20efd191a0fa3086c2466aa9a1169628826ac8f5fb78983e`.

Приватний ключ з власницької резервної копії та ключ, уже налаштований у GitHub Secrets, мають саме цей сертифікат. Проблемою запуску Actions 38321091439 був інший жорстко заданий сертифікат Lab03 у скрипті збірки.

Виправлення розділяє два наявні профілі. `lab02` створює Update02 з тим самим package та сертифікатом, versionCode 7 і версією 0.3.3. Типовий `lab03` зберігає `com.fiskerwarm.lab03` та сертифікат `3c1716e279eb2a9cfc8b1c90d54845a2cb74a92ecc1df3bf2dc0955a2b39be74`. Вихідний Manifest залишається Lab03; для Lab02 package замінюється лише в тимчасовому Manifest збірки.

Таким чином, ключі різних застосунків не підміняються, а власник 0.2.0 отримує APK для оновлення своєї програми без необхідності її видаляти. Це перевірка Android-ідентичності артефакту, а не фактичне встановлення на телефоні або тест обігріву.

Ключі, паролі й резервна копія не додаються до репозиторію чи Artifacts. Список профілів містить лише публічні відбитки сертифікатів. Невідомий відбиток відхиляється.
