- Вихідний код прочитано. У ньому немає реалізації або увімкнення команди старту клімату; усі дозволені UDS `22F195`, `22F188`, `22F191` адресовано PKC, ECC, BCM, ICC із відомими на 04.10.2026 адресами.
- Базові 111 тестів JVM повторно виконані та пройдені. Після виправлень 0.1.1 виконані 114 тестів JVM, усі пройдені.

## Виявлений дефект

Після натискання «Зупинити й роз'єднати» обробник UI викликав `probe.cancel()` та **негайно** `setBusy(false)`, хоча `done` старої BLE-сесії ще не був викликаний. Через це користувач міг почати нове сканування до завершення старого callback; пізній `done` старої сесії міг торкнутися спільного поля `probe` й UI нової сесії.

## Виправлення 0.1.1

1. Утримувати UI у busy після cancel, поки не надійде `done`.
2. Використовувати одночасно лише одного власника активного пробного сеансу через `ProbeGate` та однозначний токен сесії.
3. Ігнорувати completion застарілого токена; не запускати BLE-сканування, якщо застосунок у фоні.
4. Закривати GATT, якщо дуже ранній callback завершив сесію ще до повернення `connectGatt()`.
5. Додано три автономні тести заборони паралельних сеансів і застарілих callback.

## Що залишилося невідомим

- Реальні BLE рекламована назва та UART UUID твого vLinker FD+.
- Справжні відповіді ELM та ECU після підключення Android.
- Струм спокою Ocean і вплив постійно зеленого POWER-індикатора адаптера.
- Авторизований транспорт та протокол запуску/зупинки клімату через PKC21.3, підтверджене пробудження та незалежний тайм-аут.

## Найближчий тест на автомобілі

Для перевірки вихідного каналу достатньо встановленого Lab 0.1.0 на S24 Ultra: авто розбуджене штатно, стоїть у P, власник поруч; закриті всі інші програми OBD. Почати лише з кнопки «Оглянути BLE GATT без записів» для **свого** адаптера, зберегти JSON і передати на аналіз. У 0.1.0 після натискання «Зупинити» не розпочинати нову діагностику до отримання «Перевірка завершена». Не тестувати кліматичні CAN-команди і не робити нічних експериментів зі сном.

Наступний етап після успішної GATT-карти — окремий ATRV, після допустимої напруги — коротке одноразове читання DID за планом CAR-TEST-PLAN-UA.md. Якщо UUID невідомий або дані неповні, завершити й проаналізувати журнал перед зміною коду. Жодної обіцянки запуску обігріву в цьому тесті немає.
