## Одна процедура біля автомобіля

1. Встановіть APK поверх 0.3.4; видалення програми не потрібне. Старі журнали залишаються архівними.
2. Авто пробуджене штатним способом, P, стоянкове гальмо, власник поруч зі штатним ключем. Інші OBD-програми закриті; немає оновлення ПЗ чи попереджень живлення. Позначте контрастний checkbox умов.
3. «Підключити Vgate», виберіть свій FD-IOS, дочекайтеся завершення перевірки налаштувань.
4. Натисніть тільки **«Контроль CAN RX · 0E9 → 373 → 0E9»**, підтвердіть пасивний контроль і дочекайтеся завершення. HMI ON/OFF тест і старі 30-секундні записи не повторюйте. Клімат під час контролю перемикати не потрібно. За нульового RX програма сама перевірить альтернативний точний CRA для того самого ID; жодного широкого моніторингу.
5. «Експортувати журнал» → зберегти JSON. Після завершення від'єднайте Vgate. Для дострокової зупинки — «Зупинити»; при непідтвердженому prompt/reset або попередженні авто — фізично від'єднайте адаптер.

0E9 тут — короткий позитивний контроль попередньо виміряного каналу, не повернення до широкого сканування чи боротьби з flood. Після порога ≥3 кадрів ініціюється stop SPACE; кадри з того самого notification та bounded drain зберігаються повністю, тому фактичний count може бути більшим за 3. Якщо виникне BUFFER FULL, це явно неповний результат і наступні фази не запускаються.

За 0E9 до/після та нульового 373 через обидва API загальна несправність поточного monitor/RX значно відсіюється; залишається видимість конкретного ID/матриця/маршрутизація. За нульового 0E9 висновки про HVAC робити не можна. За появи ID тільки через CRA маємо конкретний привід дослідити API фільтрів. Новий журнал розділяє GATT write, прийняте raw RX, валідний CAN frame та декодування; жоден статус не означає «клімат увімкнено».
